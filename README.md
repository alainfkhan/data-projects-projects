## Explaining groups

A group is simply a directory in this folder.
If a folder: `some-group` is created in any way, then a new group: `some-group` is formed and can be seen by the CLI tool.

The current configuration of groups:

| Group name     | User-defined? | Original intention                  | Current use                                      | In-use? |
| -------------- | ------------- | ----------------------------------- | ------------------------------------------------ | ------- |
| `main`       | system        | Dir. for current projects           | -                                                | N       |
| `playground` | system        | Sandbox dir.                        | Project dump                                     | Y       |
| `.hidden`    | system        | Dir. to hide projects               | -                                                | N       |
| `.trash`     | system        | Staging dir. before actual deletion | -                                                | N       |
| `static`     | user-defined  | -                                   | Projects using a windows stack for data-cleaning | Y       |
| `macos`      | user-defined  | -                                   | Projects exclusively for macos                  | Y       |

> [!NOTE]
>
> - Groups: `main`, `playground`, `.hidden`, and `.trash`, are currently not being used as originally intended.
> - Groups: `static`, and `macos` were created by the user.

The CLI tool is able to change a project's group.
Because groups are directories, changing the group of a project means moving the project from one directory to another.
E.g.

- Project: `some-project` is in group: `playground`.
- Changing its group from `playground` to `main`, 
- means changing it's directory from `playground/some-project` to `main/some-project`.

The path generated by a tool connection to a file, folder, or a db, within the project has to be revised whenever a project is moved.
Therefore, in this iteration, any projects anticipating a tool connection, must stay in one group to avoid the hastle of revising all connection paths.

## Defining groups

> [!IMPORTANT]
>
> - Groups: `static`, and `macos` were unfortunately intended to bind a data project to an OS.
>   - This means a data project created in group: `macos` requiring reporting in PowerBi, necessitates a group change to maintain consistency in group definitions.
>   - But changing a project's group after creation is discouraged.
> - Future iterations of groups will not bind data projects to an OS.

A data project usually has stages:
    - Data-cleaning
    - Reporting

|                   | Data-cleaning | Reporting |
| ----------------- | ------------- | --------- |
| Windows stack     | `static`    | other     |
| Non-windows stack | other         | other     |

Any project requiring any windows stack for data-cleaning such as:
    - SQL Server Management Studio
    - PowerBI
    - Excel[^1]
    - PowerQuery
    - PowerPivot
is a project that ought to be in group: `static`.

Any project where data-cleaning was not done on a windows stack but requires reporting on a windows stack can be in any non-exclusive OS group.

> [!IMPORTANT]
> Non-windows stack data-cleaning projects in `static` is discouraged.
